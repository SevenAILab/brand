# Skill 踩坑与回归用例

维护 `brand-naming-studio` Skill 本身时读这个文件。它记录命名任务里模型容易重复犯的错，以及每次改 Skill 后应该怎样验证。

---

## 一、设计原则

这个 Skill 不是随机起名器说明书，而是品牌命名顾问的工作记忆。新增规则前先问：

```text
这是不是模型已经默认会做的事？
这是不是品牌命名任务里反复出现的真实失败？
这条规则会不会把模型绑死，导致它不能按定位变形？
这条规则是否更适合放到 references/ 或 scripts/？
```

能用脚本抓的格式问题，不要只靠文字提醒。能放参考文件的长说明，不要塞进 `SKILL.md`。

---

## 二、高价值踩坑

### 1. 直接吐名字，跳过定位

表现：
- 用户只说一句需求，模型立刻给 50 个名字。
- 候选很多，但方向混乱，无法判断好坏。

修复：
- 先用 2-4 个关键问题补定位。
- 如果用户要求直接给，先声明推断定位和约束，再进入快速冲刺。

### 2. 把数量当质量

表现：
- 输出几十个相似名字。
- 没有方向页、没有筛选逻辑、没有 shortlist。

修复：
- 输出至少 3 个差异明确的方向。
- 每个方向只给少量候选，附命名逻辑和初步风险。
- 最终必须收敛推荐，而不是让用户自己挑。

### 3. 漏掉真实世界风险

表现：
- 说“这个名字很好”，但没有 `[商标待核实] [域名待核实] [账号待核实] [语义待核实]`。
- 只讲好处，不讲最大风险。

修复：
- 所有未核实候选都带待核实标记。
- shortlist 必须有“最可能死在哪”。
- 不要编造域名、商标、账号可用性。

### 4. 英文命名掉进 AI slop

表现：
- 候选大量出现 `-ly / -ify / -ora / -exa / -ium`。
- 看起来像生成器拼词，发音和拼写都不自然。

修复：
- 造词可以保留，但必须发音清楚、语感独立、不是可替换后缀拼装。
- 对 slop 候选直接标“不推进”，不要带进 shortlist 装样子。

### 5. 中英双命名没有配对

表现：
- 左边三个中文名，右边三个英文名，用户还要自己配。
- 中英候选气质不一致。

修复：
- 必须按“同隐喻 / 同气质 / 同语言游戏”输出配对。
- 配不上的时候诚实说明，不要硬配。

### 6. 重命名时被旧名字绑架

表现：
- 用户明显因沉没成本坚持旧名，模型顺着安慰。
- 没有比较继续硬扛和换名的长期成本。

修复：
- 先做沉没成本剥离三问。
- 明确指出旧名依恋可能来自熟悉感，不等于质量高。

## 三、触发回归用例

应该触发：

```text
帮我给这个 AI 产品起个名字。
这几个品牌名哪个好？
我觉得现在公司名不对，帮我重命名。
给我做一套中英文品牌命名方案。
帮我评估这个名字有没有域名/商标风险。
我想做一个起名网站，帮我设计 naming agent 流程。
这些名字太像 AI 生成器了，帮我重做。
```

不应该触发：

```text
帮我给 Python 变量起名。
这篇文章标题怎么写？
帮我翻译一个产品说明。
给这个文件夹取个临时代号。
帮我设计一个 REST API。
```

如果应该触发但没有触发，增强 `description` 里的用户说法；如果不该触发却触发，收窄 Skill 范围，不要把所有“命名”都包进品牌命名。

## 四、功能回归用例

### 用例 A：一句话起名

输入：
```text
帮我给一个 AI 会议纪要工具起名，中文为主。
```

期望：
- 先问 2-4 个关键问题，或声明推断定位后走快速冲刺。
- 输出 3 个方向，而不是一堆同质候选。
- 候选带逻辑和待核实标记。

### 用例 B：已有候选评审

输入：
```text
帮我评估：灵会、会记、MeetingMind、Minutesly。
```

期望：
- 不重新生成 50 个名字。
- 用五标准 + fatal flaw 表格评估。
- 明确推荐、待定、不推进。

### 用例 C：中英双命名

输入：
```text
给一个中文教育出海品牌做中英双命名。
```

期望：
- 输出配对方案。
- 每对说明共享隐喻、气质或语言游戏。
- 补跨语言风险和发音提示。

### 用例 D：Skill 自身维护

输入：
```text
同样逻辑，优化这个 Skill。
```

期望：
- 改持久文件，而不是只在对话里解释。
- 检查 `SKILL.md`、`references/`、`assets/`、`scripts/` 是否同步。
- 跑 `quick_validate.py` 和输出检查脚本。

## 五、改动后验收清单

```text
[ ] SKILL.md 仍然只保留路由、硬规则和主流程
[ ] 新增规则有明确失败场景，不是通用品牌常识
[ ] 参考文件地图能找到新增文件
[ ] 如果改了输出规范，scripts/check_naming_output.py 已同步
[ ] quick_validate.py 通过
[ ] check_naming_output.py 能抓缺少待核实标记、缺少 fatal flaw、AI slop 后缀
```
